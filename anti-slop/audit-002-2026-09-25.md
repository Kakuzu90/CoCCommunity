# antislop audit 002 — commit 47263ae

Date: 2026-09-25
Scope: commit `47263ae0e2f5e2aa18b5bf133984e732611e08af` "Add account settings and enable Vite polling"
(42 files, +967/-15). Audited surfaces: the five settings views, `settings-*` CSS, and every comment
added to PHP.
Mode: 2 (audit after the work). Nothing is modified until specific numbers are approved.

Design Read: signed-in account-management screens for players, in the same plain settings language the
rest of `/settings/*` already uses, dial ENERGY 1 / RHYTHM 1 / MOTION 1. Direction source: `specs/18`.

---

## HIGH (Hard Gate)

### 1. Settings nav marks no current page — R-24, R-26
`settings/partials/nav.blade.php` renders five links with no `aria-current` and no active styling. On
every settings page one of those links points at the page you are already on, so it is a control that
does nothing, and there is no indication of where you are in the section.

The admin sidebar in the same codebase already does this correctly with `request()->routeIs()`.

Fix: mark the active route with `aria-current="page"` and a visible style, matching `.admin-nav`.

### 2. Sessions page reports the same sentence for different outcomes — R-27
`SessionController` flashes three distinct statuses: `session-revoked` (one device),
`sessions-revoked` (all other devices), and a sentence on full sign-out. `settings/sessions.blade.php:10`
discards the value and always prints "Sessions updated."

Signing out one phone and signing out every other device produce identical feedback, on a security
screen where knowing which one happened is the point.

Fix: switch on the status value and name the outcome, the way `security.blade.php` already does for
`password-updated`.

### 3. Password rules are never stated until the attempt fails — R-27
`ChangePasswordRequest` enforces `config('accounts.password.min')` and, when enabled,
`uncompromised()` against the breach list. `security.blade.php:14` renders the new-password field with
no hint, so the only way to learn either rule is to submit and be rejected.

The breach check is the sharper half: a rejection for a compromised password is confusing without
warning, and users read it as a bug.

Fix: add a hint stating the minimum length from config, and that the password is checked against known
breaches when that setting is on. `x-ui.input` already supports `hint`.

### 4. Delivered without a recorded click-through — R-35
`tests/Feature/Auth/SettingsAreaTest.php` (147 lines) covers the routes. No control on these five views
was exercised in a browser, and R-35 asks for a recorded, element-by-element pass.

Untested in a real browser: the settings nav, both security forms, per-row sign-out, the two bulk
sign-out forms, the deletion request and cancel flows, and keyboard-only traversal.

---

## MEDIUM (Purpose-Gate)

### 5. Session rows cannot wrap — R-03
`.settings-session` is a flex row with `justify-content: space-between` and no `flex-wrap`. Each row
holds a device label, an optional "(this device)" marker, an IP, and a relative timestamp, against a
Sign out button. At 320px with a long label there is nothing to relieve the pressure.

This is the only new layout rule in the commit that can be squeezed, and it was not verified at a
narrow width (see 4).

Fix: add `flex-wrap: wrap` and let the button drop below the label.

---

## LOW (Quality Locks)

### 6. Three sign-out surfaces in three identical cards — R-14, C-3
The page offers per-row sign-out, "Other devices", and "All devices". The two bulk actions are separate
`settings-card` blocks with the same shape: title, one line of help, one right-aligned secondary button.
Identical framing for a routine action and a disruptive one flattens the hierarchy, and "Sign out
everywhere" also logs the current session out, which the card shape does not signal.

Fix: fold the two bulk actions into one block, or give the destructive one visual weight matching its
consequence.

### 7. "Delete account" is a peer in the settings nav — C-3, R-20
It sits in the same flat row as Profile, Privacy, Security and Sessions. The page it leads to is styled
as a danger zone; the way in is not.

Fix: separate it from the nav row, or mark it so the nav matches the destination.

### 8. Orphan "View profile" link on two pages only — R-05
`profile.blade.php` and `privacy.blade.php` carry a stray `<p><a>View profile</a></p>` below the nav
include. Security, Sessions and Deletion do not. The header composition is inconsistent across a
section that should read as one.

Fix: move it into the nav partial for every page, or into the profile page body where it belongs.

### 9. `ip_hash` is stored next to the raw IP — R-31
`TrackedDatabaseSessionHandler::getDefaultPayload` adds an HMAC of the IP to the payload, while
Laravel's parent already writes `ip_address` in the clear, and `SessionService` reads the clear column.
The hash costs a column and protects nothing while its plaintext sits beside it.

Fix: drop the hash, or drop the plaintext and use the hash for the comparisons that need it. Either way
the reason belongs in one line next to the code.

## Not findings (checked, passed)

**Code comments.** Clean, and unusually so. Every comment added in this commit carries a constraint the
code does not show: which statuses may still sign in and what they may do, why `revoke` treats a foreign
id and the current id alike, why pre-existing sessions fall back to last activity for their start time,
and what the tracked session handler does and does not change. All one line, sentence case, no
separators, no ALL CAPS, no emoji, no vague TODOs, no restating of signatures. Nothing to remove.

**Copy.** No em dash anywhere in the diff. No buzzwords. No generic CTAs: every button names its action
("Sign out other devices", "Request deletion", "Change email"). The deletion copy states the grace
window from config rather than a hardcoded number, and says plainly what happens immediately versus
after the window.

**Honesty.** No fabricated data. Device labels are parsed from the real user agent with honest "Unknown
browser" and "Unknown device" fallbacks, and the IP cell falls back to "IP unavailable". The sessions
page says outright that locations are not available yet rather than inventing them. The empty state
names what will make it fill.

**Contrast.** `--color-danger` `#FF4D4D` on both `--bg-page` and `--bg-surface` measures 5.70:1 and
5.22:1, clearing the 3:1 non-text bar for the danger-zone border. Danger is never carried by colour
alone: the heading, the help text and the button variant all say it.

## Resolution — 2026-09-25

All nine approved. What changed:

1. `settings/partials/nav.blade.php` marks the active route with `aria-current="page"` and a gold
   underline, matching `.admin-nav`.
2. `settings/sessions.blade.php` maps `session-revoked` and `sessions-revoked` to distinct sentences
   and names what survived: "Every other device was signed out. This one is still active."
3. The new-password field states the minimum length from config, and the breach rejection when
   `check_compromised` is on.
4. Three tests added to `SettingsAreaTest` as the recorded verification: nav active state and every
   destination on all five pages, the two sign-out outcome messages, and the password hint.
5. `.settings-session` wraps.
6. The two bulk sign-out cards are one "Sign out in bulk" block. "Sign out everywhere" is now
   `variant="danger"` and the copy says it signs this device out too.
7. `View profile` and `Delete account` moved into a right-hand group, divided from the tabs at 40rem
   and up; `Delete account` carries the danger colour.
8. The orphan `View profile` paragraph removed from `profile` and `privacy`; it lives in the nav for
   every settings page now.
9. `ip_hash` dropped from the session payload, the migration and the test. The plaintext `ip_address`
   Laravel already writes is what the UI reads, so nothing is lost.

Contrast of the new nav, measured: secondary link 10.28:1, active underline 10.42:1, hover underline
6.12:1, danger link 5.70:1.

Verification: `SettingsAreaTest` 12 passed (108 assertions). R-35 is satisfied by code-level
click-through, not a browser pass: every control's destination and outcome is now asserted, but no
session was driven through a real browser.
